    80→### VLM SDK call (verified via the VLM skill)
    81→
    82→```ts
    83→const ZAIModule = await import("z-ai-web-dev-sdk");
    84→const ZAI = (ZAIModule as { default?: unknown }).default ?? ZAIModule;
    85→const zai = await (ZAI as { create: () => Promise<VLMClient> }).create();
    86→const completion = await zai.chat.completions.createVision({
    87→  messages: [{
    88→    role: "user",
    89→    content: [
    90→      { type: "text", text: prompt },
    91→      { type: "image_url", image_url: { url: dataUrl } },
    92→    ],
    93→  }],
    94→  thinking: { type: "disabled" },
    95→});
    96→```
    97→
    98→Key learnings:
    99→- The vision method is `chat.completions.createVision(...)` — NOT
   100→  `chat.completions.create(...)`.
   101→- SDK is dynamic-imported inside the route handler so it can never end
   102→  up in a client bundle.
   103→- `content` may be string OR array of content blocks; `contentToString()`
   104→  handles both, plus an object-with-`.text` shape.
   105→- Strict-JSON prompt + loose JSON parser (strips ```json fences, extracts
   106→  first `{...}` block). On parse failure, falls back to a row with null
   107→  species + raw text in `notes` so the UI surfaces a graceful state.

Severity: `pressureHpa` inverse (lower=worse) per spec. **Documented deviation:** `visibilityM` is also treated as inverse because the seeded thresholds (caution=5000, high=2000, critical=1000) only make sense under lower=worse semantics — following the spec literally would flag clear-weather visibility (10000m) as CRITICAL. Rationale is in the source comment on `severityFor()`.
   314→7. Metric→type: wind→WIND, wave→WAVE, precipitation→RAIN, visibility→VISIBILITY, pressure→STORM.
